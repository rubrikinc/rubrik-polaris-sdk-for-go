# CLAUDE.md

## Repository Overview

**rubrik-polaris-sdk-for-go** is the official Go SDK for Rubrik Security Cloud
(RSC). It wraps the RSC GraphQL API into idiomatic Go types and methods,
consumed primarily by the `terraform-provider-polaris` Terraform provider.

- **Module:** `github.com/rubrikinc/rubrik-polaris-sdk-for-go`
- **Go version:** 1.24+
- **License:** MIT
- **Main branch:** `main`

## Key Directories

| Path | Description |
|------|-------------|
| `pkg/polaris/graphql/` | Domain packages — each subdirectory wraps one RSC API area |
| `pkg/polaris/graphql/*/queries/` | `.graphql` source files (source of truth for queries) |
| `pkg/polaris/graphql/regions/` | Typed region packages (`aws`, `azure`, `gcp`) |
| `pkg/polaris/graphql/core/` | Shared types, enums, permissions, feature flags |
| `pkg/polaris/` | High-level API wrappers (aws/, azure/, gcp/, access/, etc.) |
| `internal/handler/` | Mock HTTP server for unit tests |
| `internal/assert/` | Test assertion helpers |
| `cmd/` | CLI tools: `schema` (introspection), `testenv` |

## Two-Layer Architecture

`pkg/polaris/graphql/<domain>/` — thin GraphQL wrappers: types, queries,
direct API calls. Add new RSC API surface here.

`pkg/polaris/<domain>/` — high-level API: business logic, validation,
orchestration over the GraphQL layer. Add user-facing SDK methods here.

Always determine which layer a change belongs to before editing.

## GraphQL Code Generation

`.graphql` files in `queries/` are compiled to `queries.go` by `queries_gen.go`.

**Workflow:** Edit `.graphql` -> run `/rx-queries` -> commit both files.

**Rules:**
- NEVER manually edit `queries.go` (header: `// Code generated by queries_gen.go DO NOT EDIT.`)
- Operation name MUST be `RubrikPolarisSDKRequest` (queries and mutations)
- Result MUST be aliased to `result:`
- Extrapolate input fields as individual `$variables` — never pass complex input types

```graphql
mutation RubrikPolarisSDKRequest($cloudAccountId: String!, $name: String!) {
  result: updateAwsCloudAccount(input: {
    cloudAccountId: $cloudAccountId,
    name: $name,
  }) {
    id
  }
}
```

## Code Rules

- MIT license header on every source file (copyright Rubrik, Inc.)
- Doc comments on all exported functions and types
- Use `secret.String` from `pkg/polaris/graphql/core/secret` for credentials
  and tokens — never bare `string`
- Use typed regions, never `string`:
  - AWS: `aws.Region` from `.../graphql/regions/aws`
  - Azure: `azure.Region` from `.../graphql/regions/azure`
  - GCP: `gcp.Region` from `.../graphql/regions/gcp`
  - Parse with `RegionFromAny()`, validate against `RegionUnknown`
- Read existing adjacent code before editing — follow established patterns
- Inject dependencies for testability; prefer fakes over mocks

## Testing

- Use `internal/handler/` for mock HTTP servers — not `testify/mock` or `httptest` directly
- Use `internal/assert/` for test assertions
- CamelCase test function names
- Integration tests require `TEST_INTEGRATION=1` and RSC credentials in
  `~/.rubrik/polaris-accounts.json`

## Pre-Commit Checklist

1. `go fmt ./...`
2. `go vet ./...`
3. `staticcheck ./...`
4. `/rx-queries` (if any `.graphql` files changed)
5. `go test ./...`

Run `/rx-checks` to execute all of the above automatically.

## Commit Messages

Follow the seven rules of a great Git commit message (https://cbea.ms/git-commit). Key points: subject line ≤50 chars, imperative mood, no trailing period. Use a body only when the WHY is non-obvious from the diff — not to list every file changed.

## Pull Requests

Read `.github/pull_request_template.md` before creating a PR and fill it in faithfully. If how the change was tested isn't clear from context, ask. Don't remove unchecked checkboxes. Don't hard-wrap prose — write paragraphs as single lines and let GitHub handle wrapping.

## Versioning

SemVer (`vMAJOR.MINOR.PATCH`). Update CHANGELOG for every user-visible change.
